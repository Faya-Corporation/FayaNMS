     1→# Network Management, Configuration Backup, Change Management & Reporting Platform
     2→
     3→## 1. Project Overview
     4→
     5→### Project Name
     6→
     7→**FAYA Network Operations Management System — FayaNMS**
     8→
     9→Working product name:
    10→
    11→**FayaNMS — Network Configuration, Change, Incident & Performance Management Platform**
    12→
    13→### Purpose
    14→
    15→FayaNMS will provide a centralized platform for managing enterprise network infrastructure across multiple vendors and locations.
    16→
    17→The system will combine:
    18→
    19→- Network device inventory
    20→- Automated device discovery
    21→- Configuration backup
    22→- Configuration versioning
    23→- Configuration comparison
    24→- Configuration restore
    25→- Configuration compliance
    26→- Network API management
    27→- Credential management
    28→- Change management
    29→- Approval workflows
    30→- Automated configuration deployment
    31→- Incident management
    32→- Network monitoring
    33→- Performance monitoring
    34→- Capacity reporting
    35→- Availability reporting
    36→- SLA reporting
    37→- Audit logging
    38→- Configuration drift detection
    39→- Network topology
    40→- Alerting and notification
    41→- Scheduled and on-demand reports
    42→- PDF/Excel/CSV exports
    43→- Multi-vendor device integration
    44→
    45→The platform must be designed around a **vendor-independent core with pluggable device adapters**.

    48→
    49→# 2. Primary Business Objectives
    50→
    51→The platform should provide one operational system for the complete network-management lifecycle:
    52→
    53→**Discover → Inventory → Monitor → Backup → Detect Change → Request Change → Approve → Execute → Validate → Rollback if required → Audit → Report → Incident/RCA**
    54→
    55→The principal objectives are:
    56→
    57→1. Ensure every managed network device has a recent configuration backup.
    58→2. Maintain historical configuration versions.
    59→3. identify unauthorized configuration changes.
    60→4. enforce controlled network changes.
    61→5. provide complete change approval history.
    62→6. automate pre-change and post-change checks.
    63→7. provide reliable rollback mechanisms.
    64→8. detect network incidents.
    65→9. correlate incidents with recent configuration changes.
    66→10. monitor device and link health.
    67→11. maintain network performance history.
    68→12. provide operational and management reports.
    69→13. expose secure APIs for integrations.
    70→14. maintain immutable audit history.
    71→15. support multiple network vendors without redesigning the application.

    75→# 3. Initial Supported Vendors
    76→
    77→## Tier 1 — Required for Production Release
    78→
    79→| Vendor | Family | Primary Integration |
    80→|---|---|---|
    81→| Cisco | Catalyst IOS / IOS XE | SSH, NETCONF, RESTCONF, SNMP, Syslog, telemetry |
    82→| Cisco | Catalyst 9K | SSH, RESTCONF, NETCONF/YANG, gNMI/MDT |
    83→| Fortinet | FortiGate / FortiOS | REST API, SSH, SNMP, Syslog |
    84→| Sophos | Sophos XGS / SFOS | Sophos Firewall API, SSH, SNMP, Syslog |
    85→| HPE Aruba | AOS-CX | REST API, SSH, SNMP |
    86→| HPE Aruba | ArubaOS-Switch / ProCurve | REST where supported, SSH, SNMP |
    87→| HPE | Comware | SSH, NETCONF where supported, SNMP |
    88→
    89→Cisco IOS XE currently exposes YANG-based configuration and operational state using RESTCONF and also supports model-driven telemetry through NETCONF, RESTCONF and gNMI. Cisco configuration archives can provide native checkpoints and rollback references.
    90→
    91→FortiGate provides REST APIs for retrieving and modifying configuration and obtaining statistics. Current Fortinet guidance uses token-based REST API administrators and recommends minimum privileges and putting API tokens in request headers. FortiOS also supports configuration backups to destinations including SFTP, FTP and TFTP.
    92→
    93→Sophos Firewall 22 provides configuration APIs, with API access disabled by default and administrator/API access explicitly enabled. Sophos also provides vendor-supported backup and restore capabilities that should be orchestrated rather than replaced by unsupported backup methods.
    94→
    95→HPE Aruba AOS-CX provides a REST API covering switch configuration/state, including standard GET/POST/PUT/PATCH/DELETE operations. Current versions use authenticated HTTPS sessions and, on newer firmware, CSRF protection.

   247→                            │
   248→                      Secure TLS

   251→              │                           │
   252→         Site Collector A            Site Collector B
   253→              │                           │
   254→       Management LAN A              Management LAN B
   255→        │     │     │                 │     │     │
   256→      Cisco FortiGate HPE           Cisco Sophos HPE
   257→```

   259→Collectors provide:
   260→
   261→- SSH proxy
   262→- API proxy
   263→- SNMP polling
   264→- Syslog ingestion
   265→- telemetry reception

   267→- local job queue
   268→- temporary encrypted cache
   269→- retry during WAN failure

   630→# 19. Configuration Restore
   631→
   632→Restore must be a controlled workflow.
   633→
   634→Never provide an unrestricted one-click restore without checks.
   635→
   636→Workflow:
   637→
   638→```text
   639→Select configuration
   640→       ↓
   641→Create change request
   642→       ↓
   643→Approval
   644→       ↓
   645→Take current backup
   646→       ↓
   647→Compatibility check
   648→       ↓
   649→Restore
   650→       ↓
   651→Device reconnect
   652→       ↓
   653→Health validation
   654→       ↓
   655→Configuration validation
   656→       ↓
   657→Close / rollback
   658→```
   659→
   660→Sophos deserves particular handling: vendor-native backup compatibility and interface mapping rules can vary between platforms/models, so FayaNMS should store the original vendor-supported artifact and perform compatibility checks before allowing restoration.

   901→# 26. Pre-Change Checks
   902→
   903→Before executing any automated configuration:
   904→
   905→Check:
   906→
   907→```text
   908→Device reachable?
   909→Authentication valid?
   910→Expected device identity?
   911→Firmware supported?
   912→HA healthy?
   913→CPU acceptable?
   914→Memory acceptable?
   915→Management interface reachable?
   916→Current configuration backed up?
   917→Configuration changed since approval?
   918→Maintenance window active?
   919→Another change running?
   920→Rollback method available?
   921→```
   922→
   923→If the configuration has changed after approval:
