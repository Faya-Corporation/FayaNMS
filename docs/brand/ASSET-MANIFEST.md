## 1. Tier 1 — Brand masters (`public/brand/`)

Governed masters; treat as immutable artifacts — regenerate or replace via the pipeline, never hand-edit in place.

**Generation model (re-audit B1-005/013/014, enforced since R2):** the five mark-family masters
(`fayanms-mark`, `-brand`, `-micro`, `-mono`, `-white`) plus `public/logo.svg` and `src/app/icon.svg`
are **geometry-derived** — regenerated by `bun run brand:raster` from `src/lib/brand/mark-geometry.ts`.
`brand:validate` re-derives each of them byte-for-byte from that module, so a hand edit (or a stale
committed copy) fails validation. The wordmark/lockup SVGs remain **hand-authored typographic
templates** (flexible-typography policy, re-audit B2-023): they may render with a fallback
sans-serif when Inter is unavailable and are **not** guaranteed pixel-identical across systems.

## 4. Raster derivatives (generated by `bun run brand:raster`)

Produced by `scripts/generate-brand-raster-assets.ts` (sharp) from the shared composition module
`scripts/brand-raster-composition.ts`, which consumes the single geometry source
`src/lib/brand/mark-geometry.ts` and the identity palette from `FAYANMS_BRAND` — no raster or SVG
derivative is hand-maintained. **Regenerate — never hand-edit:**

| Generated file | Size | Source | Usage |
|---|---|---|---|
| `public/brand/app-icon-192.png` | 192×192 | Brand-blue tile + white full mark (`mark-geometry`) | PWA manifest icon |
| `public/brand/app-icon-512.png` | 512×512 | Brand-blue tile + white full mark (`mark-geometry`) | PWA manifest icon, store-style slots |
| `public/brand/app-icon-maskable-192.png` | 192×192 (full-bleed, 80% safe zone) | Brand-blue field + white full mark (`mark-geometry`) | Manifest `purpose: "maskable"` |
| `public/brand/app-icon-maskable-512.png` | 512×512 (full-bleed, 80% safe zone) | Brand-blue field + white full mark (`mark-geometry`) | Manifest `purpose: "maskable"` |
| `src/app/favicon.ico` | PNG-in-ICO with exactly **16/32/48** entries | White tile + brand-blue **micro-mark** (`MARK_MICRO_GEOMETRY`) | Browser favicon fallback (canonical path — B2-026) |
| `public/brand/github-social-preview.png` | **1280×640** | Social-card composition (solid primary/accent bars, mark, `FAYANMS_BRAND` strings) | GitHub repository social preview (upload is a GitHub-settings action — see [SOCIAL-REPOSITORY.md](./SOCIAL-REPOSITORY.md)) |

Enforcement (re-audit §9.5 made executable): `brand:validate` **sharp-checks every dimension above**,
re-renders each PNG through the *same* composition module and compares decoded raw pixels, rebuilds
the ICO via `buildIco()`/`faviconTileSvg()` and byte-compares it, and structurally parses the ICO
container (header, entry count, per-entry PNG dimensions). A stale or tampered derivative fails
the gate — re-run `bun run brand:raster` and commit.

## 5. Validation contract

Three scripts gate brand integrity (wired into `package.json`; `brand:audit` chains all three).
They are the enforcement authority; if a check here and the script disagree, the script wins and
this document gets fixed. The lists below mirror the scripts' ✓ outputs (verified 2026-09-10).

### `bun run brand:validate` (`scripts/validate-brand-assets.ts`)

Fails when:

- the governed `public/brand/` inventory is not **exactly** the canonical set (12 SVG masters + README + 5 generated PNGs): missing governed master, **unknown extra file**, invalid extension, or two files mapping to the same semantic role;
- a generated SVG master (`fayanms-mark`, `-brand`, `-mono`, `-white`, `-micro`, `public/logo.svg`, `src/app/icon.svg`) is **stale** — the validator re-derives each from `src/lib/brand/mark-geometry.ts` (`renderFayaNMSMarkSvg`) and byte-compares, so hand edits fail;
- a brand SVG (`public/brand/*.svg` + `public/logo.svg`) has an invalid root or contains script, animation, filters, `<style>`, foreignObject, or external/remote references (`<text>` is allowed — wordmark/lockup masters are text-based by policy);
- any runtime icon master under `public/icons/fayanms/` breaks the **exact Tier-2 root contract** (`viewBox="0 0 24 24"`, `fill="none"`, `stroke="currentColor"`, `stroke-width="2"`, round caps/joins, verbatim double-quoted), contains gradients/filters/styles/scripts/animation/external refs, paints with any **hardcoded color** other than `none`/`currentColor`, or has a non-kebab-case filename;
- brand-colored masters (`fayanms-mark-brand.svg`, `public/logo.svg`, `src/app/icon.svg`) do not paint with `FAYANMS_BRAND.colors.primary` or embed any hex that is not an allowed master color (primary / `#FFFFFF` / `#000000`) — colors are validated against the **imported** `FAYANMS_BRAND`, never a duplicated palette;
- a raster derivative has wrong dimensions (sharp-verified): app-icon-192/512, maskable-192/512 at 192/512², `github-social-preview.png` at **1280×640**;
- a raster derivative is **stale**: each PNG is re-rendered through the shared composition module (`scripts/brand-raster-composition.ts` — the exact `brand:raster` code path) and raw pixels are compared; `src/app/favicon.ico` is rebuilt via `buildIco()` + `faviconTileSvg()` and byte-compared;
- `src/app/favicon.ico` is not a valid PNG-in-ICO container with exactly 16/32/48 entries decoding to those dimensions;
- `layout.tsx` references an external http(s) icon/logo URL (BRAND-001), a file-based metadata file (`icon.svg`, `favicon.ico`, `apple-icon.tsx`, `opengraph-image.tsx`, `twitter-image.tsx`, `manifest.ts`) is missing, or `public/logo.svg` is animated;
- OG/Twitter/`social-card.tsx` artwork contains a **gradient** (B1-007 guard — solid primary/accent composition only);
- `src/app/icon.svg` contains a `<line>` — it must be the micro-mark (no connectors), proving the favicon policy (B1-014).

### `bun run brand:validate-icons` (`scripts/validate-icon-registry.ts`)

Fails when:

- the `FayanmsIconName` union in `src/lib/icons/types.ts` is not **exactly** the disk file set (missing or phantom entry) — currently **228/228**;
- a disk master violates the exact Tier-2 geometry contract (same rules as above — B1-008);
- **catalog parity** (B1-009) breaks: a disk master missing from [ICON-CATALOG.md](./ICON-CATALOG.md), a catalog row with no disk file ("phantom"), a duplicate catalog row, or the catalog row count ≠ disk count (the **rows** are authoritative, not the header total);
- a sidebar view key has no `NAVIGATION_ICONS` entry, or any registry target (nav/vendor/device) is missing on disk;
- **vendor validation** (B1-011): every adapter in the real driver registry (`src/lib/vendors/drivers.ts` `driverCatalog`) must resolve past `vendor-generic` (unless its vendor *is* `generic`) and have a display label — the list is **derived from the registry**, so a new adapter fails the gate until a governed glyph + mapping exists;
- **device-role validation** (B1-012): every `DEVICE_ROLE_META` role must resolve via `deviceIconFor()` to exactly the icon its metadata declares, exist on disk, and get a real label from `deviceIconLabelFor()` (never the old generic "Device type glyph"); the ten previously-generic roles (e.g. `TOP_OF_RACK`, `WAN_GATEWAY`, `WIRELESS_CONTROLLER`, `LOAD_BALANCER`) must not fall back to `device-generic`, while unknown roles still must.

Warnings (never affect the exit code):

- cataloged masters currently unused by runtime (B1-010 orphan policy: disk⇔union⇔catalog must be exact; **runtime-unused masters are allowed** — the kit is a reusable catalog; referenced-but-missing still fails). There is no must-use list yet;
- a stale `Total icons:` header in the catalog that disagrees with the authoritative row count.

### `bun run brand:validate-consumers` (`scripts/validate-brand-consumers.ts`)

Scans `src/**/*.{ts,tsx}` (comment-stripping, string-aware) and fails on the exact re-audit regressions:

- **R1 Waypoints** — the Lucide `Waypoints` glyph anywhere in `shell/`, `auth/`, `brand/`, or in non-allowlisted views (allowlisted topology semantics: `topology-view.tsx`, `cmdb-view.tsx`, `command-palette.tsx`); out-of-scope mentions warn;
- **R2 identity literals** — bare/quoted `FayaNMS` / `Network Operations Management` or JSX text literals in identity-composition surfaces (`shell/`, `auth/`, `brand/`, `domain/`, `layout.tsx`, `manifest.ts`); identity text must come from `@/lib/brand/identity` or the lockup components;
- **R3 raw brand hex** — `#2563EB` / `#0891B2` (any case) or `text/bg/border-[#…]` classes anywhere in `src/` outside the SoT (`identity.ts`, `mark-geometry.ts`); in-app components use token classes (`text-primary`), non-CSS consumers import `FAYANMS_BRAND` (B2-018);
- **R4 raw icon URLs** — `/icons/fayanms/` references outside the single CSS-mask renderer `fayanms-icon.tsx`;
- **R5 external identity URLs** — http(s) `.svg`/`.png`/`.ico` URLs in `layout.tsx` and `components/**` (BRAND-001);
- **R6 duplicate mark geometry** — the mark's geometry attribute signature (`cx="12" cy="8" r="1.5"` + JSX/quote variants) outside `mark-geometry.ts`.

Every allowlist entry is a documented, justified exception in the script's `APPROVED_FILES` map.

### `bun run brand:raster` (`scripts/generate-brand-raster-assets.ts`)

Not a validator — the generator for §1/§4. Re-run after any geometry or identity change; commit its
output; do not edit SVG/PNG/ICO outputs by hand (`brand:validate` re-derives them).

### `bun run brand:audit`

Chains `brand:validate` → `brand:validate-icons` → `brand:validate-consumers`; all three must be green.

## 6. Change process

1. Tier 1 change → mark-geometry/identity change → run `brand:raster` (regenerates the mark-family masters + raster set) → run `brand:validate` → update this manifest row. Never edit the generated masters in place.
2. Tier 2 change → follow [ICONOGRAPHY.md §8](./ICONOGRAPHY.md) → run `brand:validate-icons` → update catalog rows (rows are the enforced inventory).
3. Any new vendor glyph → additionally follow [VENDOR-GLYPHS.md](./VENDOR-GLYPHS.md) (project-glyph rule and future-upgrade record).
