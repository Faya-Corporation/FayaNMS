## 2. Social preview

The master is generated by the raster pipeline:

```bash
bun run brand:raster   # produces public/brand/github-social-preview.png (1280×640)
```

Upload (repository-settings action, not a commit):

1. Repository → **Settings → General** → scroll to **Social preview**.
2. **Edit → Upload new image** → select `public/brand/github-social-preview.png`.
3. Confirm the crop preview shows the full lockup (the 1280×640 master is exactly the 2:1 ratio GitHub recommends for large previews; no further cropping should be needed).
4. Save. GitHub caches aggressively — after changing the image, verify with a hard-refresh of an unfurled link (or a private window).

Notes:

- The PNG is a **generated derivative** — never edited by hand; regenerate from the Tier 1 masters if the brand changes ([ASSET-MANIFEST.md §4](./ASSET-MANIFEST.md)).
- The same construction backs the in-app OG/Twitter cards (`src/app/opengraph-image.*` / `twitter-image.*` via `ImageResponse`), so repository unfurls and app shares stay visually consistent.

## 3. Website URL field

**Deliberately left empty.** The repository Website field should only carry a real, reachable
product or documentation URL. There is no deployed product/docs site yet; a placeholder
(e.g. a localhost URL or an unregistered domain) would be a false claim. Populate it when a
real deployment or docs host exists, and record the URL here.

## 4. Badge policy (README)

The README badge row carries **factual stack badges only** — technologies the repository actually
uses, verified against `package.json` / the getting-started docs:

- ✅ Allowed: Next.js 16 · TypeScript 5 · Bun · Prisma · Tailwind CSS 4 · next-intl (EN·AR) — static `img.shields.io` badges, `style=flat-square`.
- ❌ Not allowed until real: **license badge** (no license file is selected yet — a badge would fabricate a licensing claim), **CI badge** (the gate in `docs/ci/ci-gate.yml` is ready-to-activate but not activated on GitHub — the workflow push is blocked by the PAT's missing `workflow` scope; see the README's honest-status section), **coverage**, **security-certification**, **"production ready"**, **Discord/community**, and any **vendor endorsement** badges.
- When a badge's underlying fact becomes true (e.g. a license is chosen, CI runs green on `main`), add the badge **and** keep the honest-status prose consistent with it.
