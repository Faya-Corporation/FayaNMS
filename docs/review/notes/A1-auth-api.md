Overall posture: **strong**. NextAuth credentials + 12h JWT with per-request DB revalidation (role change / deactivation propagates); every mutating `/api/v1` route carries a handler-level `requirePermission`/`requireRole`/`requireApprovalEntitlement`/service-scope check enforced by contract test (`tests/auth/authorization-contract.test.ts`); machine plane is Ed25519/HS256 service JWT with audience+issuer+expiry+scope; rate gate is pre-handler with rightmost-trusted-hop XFF; login brute-force guard keyed (source, HMAC(account)); SSRF two-plane guard on webhook egress; secrets hashed (scrypt / sha256) or vault pointers; audit hash-chain on mutations. No raw SQL (only parameterized `$executeRaw` advisory locks); no fs/path use in API routes; no secrets in API responses found.

## Explicitly checked, no finding (evidence notes)

- **NextAuth config** (options.ts): JWT strategy, 12h maxAge (was 30d), claims refreshed + stripped on deactivation; uniform failure for unknown/disabled/wrong-password (no enumeration); audit on login. Cookie flags are NextAuth v4 defaults (`SameSite=Lax`, `__Secure-` on https) — see A1-02/A1-03 for the residual.
- **Service JWT** (service-jwt.ts): alg pinned to HS256|EdDSA, trust-plane must be CONFIGURED (no `alg:none`/confusion), audience pinned, exp/iat skew ±30s, issuer allowlist, timing-safe HMAC, Ed25519-only keys, fail-tight on malformed key material. Proxy machine-surface isolation (verified token off-surface ⇒ 401) confirmed; all 11 worker routes + 3 machine-exact routes + 4 ingest routes enforce `authenticateServiceRequest` with the correct per-route scope at the handler.
- **API-client plane**: opaque sha256-hashed tokens, mutations-only, fail-closed `allowApiClients` opt-in (only alerts/acknowledge opts in), `.read` scopes refused, human-only approval/SoD preserved.
- **Rate gate**: pre-handler (no post-side-effect 429), rightmost-trusted-hop XFF, sanitized keys, named budgets for /ai and csv-import, bounded stores, optional shared Postgres store that fails closed.
- **Login guard**: pre-check + in-authorize double enforcement, HMAC-keyed account hash (non-reversible), bounded state, exponential temporary lockout, telemetry without PII; malformed bodies fail open only into NextAuth's own handling (documented).
- **Sensitive data**: no password/token/secret material in any response or audit payload reviewed (api-clients list returns prefix only, webhook secret masked + encrypted at rest + AAD-bound, credentials routes return vault pointers only, snapshots AES-256-GCM at rest, DB query logging off in production). Demo seed password exists but `FAYANMS_DEMO_MODE=true` is a production boot violation (security-policy).
- **Injection**: no `$queryRaw` string building (only parameterized advisory-lock `$executeRaw`); all input via Zod with bounded lengths; no fs/path traversal surface (downloads stream from DB with `Content-Disposition` filename sanitization); incidents/export HTML escapes with `esc()`.
- **SSRF**: webhook/notification URLs behind two-plane guard (admission + per-resolved-address delivery recheck, redirects refused); worker/probe targets are DB-sourced, user-supplied `mgmtIp` is IPv4-literal-validated — product-intended egress, documented target-policy planes.
- **IDOR spot-checks**: snapshot download/restore bind snapshot↔device; change PATCH enforces draft ownership + SoD; notifications/read is caller-scoped; actor is always the server-verified principal (client-supplied actor fields removed).
